# AI音楽部 Studio Next（Version 2）— 設計方針

既存Studio（Version 1、`~/AI Music Studio`）は**一切変更しない**。

## 1. 最初に伝えるべきこと（設計上の重大な指摘）

### 1-1. 「制作履歴・お気に入り」のPremium化 — 決定と、必要な手当て

**決定：カラスイさんの判断により、制作履歴とお気に入りは Premium に含める。**（2026-07-31）

当初こちらから「無料側に置くべき」と提案した。理由は、これらがVersion 1で既に無料で
動いており、有料化が「増える」ではなく「取り上げられる」体験になるため。
また Version 1 の憲章第三原則「データを人質にする設計は禁止」にも触れる。

この決定を前提に進めるが、**次の手当てを必ずセットで行う必要がある**。

**手当て① 既存Version 1ユーザーへのグランドファザリング**

V2はV1と別URLの新サービスなので、V1利用者から機能を奪うわけではない。
ただし移行時には確実に「減った」と受け取られる。そのため、

> Version 1 を使っていた人がVersion 2へ移行する際、**Premiumを1年間無償で付与する**

を移行計画に組み込む。**決定（2026-07-31）：期間は「永年」ではなく「1年間」。**
その後の扱いは運営状況を見て判断する。

**手当て② データは無料でも必ず取り出せるようにする**

制作履歴の**閲覧・活用UI**はPremiumでよいが、**データそのもののエクスポート**は
無料でも必ずできるようにする。ここを閉じると本当の人質化になり、憲章第三原則に反する。
プロトタイプの無料プランに「データのエクスポート」を残しているのはこのため。

この2つを守れば、Premium化しても信頼を損なわずに運用できる。

### 1-2. Premiumの価値は「毎週のコンテンツ」ではなく「プロダクトの進化」

**決定（2026-07-31）：Premiumを"定期便"として設計する案は取り下げる。**

当初こちらから「ストック型の機能では月額課金は続かないので、毎週何かが届く定期便にすべき」
と提案した。指摘そのものは正しいが、**解決策の選び方を誤っていた**。

毎週コンテンツを作る運営は、カラスイさん一人では確実に破綻する。
そして破綻した瞬間に「今週は何も来なかった」という解約理由が生まれる。
つまり定期便モデルは、リスクを減らすどころか**新しい失敗ポイントを増やしていた**。

**採用するモデル：Cursor / Notion 型（アップデートされ続ける道具）**

| | 定期便モデル（不採用） | 進化する道具モデル（採用） |
|---|---|---|
| 価値の源泉 | 毎週配るコンテンツ | プロダクトそのものが良くなること |
| 継続理由 | 「今週も何か届く」 | 「手放すと制作が遅くなる」 |
| 運営負荷 | 毎週締切がある | 締切がない。積み上げでよい |
| 破綻条件 | 1週休むと解約が始まる | 数か月止まらない限り問題ない |

Premiumで売るのは次の4つ：

1. **Studioが便利になり続ける**（新機能・改善が毎月入る）
2. **制作時間が短くなる**（テンプレート・ワークフロー）
3. **AI音楽ニュースが毎日更新される**（すでに自動化済み）
4. **ツールが増えていく**

この4つのうち3つは**すでに自動化されているか、通常の開発で自然に積み上がる**。
つまり「Premiumのために追加でやる作業」がほぼ発生しない。これが定期便モデルとの決定的な差。

AI音楽ニュースの自動更新（1日4回・全自動）が、実は最も強いPremium基盤になっている。
**何もしなくても毎日新しくなるものを、既に持っている。**

### 1-3. Premiumの本当の防御力は「カラスイさんの目利き」

プロンプトも、ニュース要約も、機能も、いずれ誰かが真似できる。
真似できないのは「Sunoで200曲作った人が、どれを使い、どれを捨てたか」という判断。

だからPremiumの中心はツールではなく、**判断を売る**設計にする。
プロトタイプの「カラスイ Picks」で、無料は事実+導入まで、Premiumは
「乗り換えるべきか、その理由3つ、代わりにこうする」まで出しているのはこの考えによる。

## 2. プロダクト構造

### 2-1. 4つの場所の役割（依頼の整理を踏襲）

| 場所 | 役割 | 指標 |
|---|---|---|
| YouTube | 出会う | 新規訪問者数 |
| **Studio** | **毎日開く** | **DAU / 継続日数** |
| Substack | 思い出す | 登録者数・開封率 |
| Premium / Master | 加速する | 継続率 |

Studioの成功指標は「訪問数」ではなく**「連続利用日数」**。
この一点に効かない機能は、後回しでよい。

### 2-2. 情報設計（ナビゲーション）

Version 1 は機能名が並ぶ「ツール置き場」型だった。
Version 2 は**目的**で分ける。

```
ホーム            ← 今日やることが決まっている場所

知る
  AI音楽ニュース
  カラスイ Picks
  AIツール図鑑

つくる
  曲一覧
  プロンプト工房
  ストーリーボード
  制作ツール

マイスタジオ
  AI秘書 / データ管理 / プラン
```

- **PC**: 左サイドバー（グループ見出し付き）
- **スマホ**: 下部タブ5つ（ホーム／ニュース／つくる／学ぶ／マイ）

スマホで下部タブにしたのは、依頼にあった「毎日開く」を満たすため。
毎日開くサービスは片手で操作できる必要がある。

### 2-3. トップページの設計思想

**トップページの仕事は、情報を並べることではなく「今日の1手を決めること」。**

参考にしたもの：
- **Apple Today** — 毎日1つ、編集者が選んだものが主役
- **Cursor / Notion** — 「前回の続き」から再開できる
- **Perplexity Discover** — 情報が"読み物"として編集されている

構成（上から順に意味がある）：

| # | ブロック | 目的 |
|---|---|---|
| ①〜④ | **曲を作る／歌詞を書く／MVを作る／プロンプトを作る** | 制作の入口。いちばん大きく |
| ⑤ | 続きから | 前回のつづきへ戻る |
| ⑥ | 今日の重要ニュース（3件） | 情報収集。主役ではない |
| ⑦ | カラスイ Picks（**1件だけ**） | 迷わせない。一覧は Picks ページ |
| ⑧ | おすすめプロンプト | ふたたび制作へ |
| ⑨ | 制作ツール | 目的が決まっている人の近道 |
| ⑩ | 今日試すAIツール | 明日また来る理由 |

「制作 → 情報収集 → 学習 → ふたたび制作」の流れになるようにしている。

**ニュース一覧をトップにしない。** ニュースは「来る理由」であって「居る理由」ではない。
居る理由は1番目のブロック（自分の制作）が作る。

## 3. アーキテクチャ

### 3-1. Version 2 最大の設計変更：アプリとコンテンツの分離

Version 1 は「アプリ」だけだった。Version 2 は**毎日更新されるコンテンツ基盤**を土台に持つ。
「毎日開きたくなる」の技術的な正体はこれ。

```
studio-next/
├── src/                    アプリ（滅多に変わらない）
│   ├── features/           機能ごとに縦割り
│   │   ├── home/
│   │   ├── news/
│   │   ├── picks/
│   │   ├── prompts/
│   │   ├── songs/
│   │   └── tools/
│   ├── core/               全機能が使う土台
│   │   ├── content/        コンテンツ取得・キャッシュ
│   │   ├── entitlement/    プラン判定（後述）
│   │   ├── storage/        IndexedDB / localStorage
│   │   └── ui/             デザインシステム
│   └── app/                ルーティング・シェル
│
├── content/                コンテンツ（毎日変わる）
│   ├── news.json           ← GitHub Actionsが自動更新
│   ├── picks.json          ← カラスイさんが書く
│   ├── tools.json
│   ├── youtube.json
│   ├── substack.json
│   └── prompts/
│       ├── free.json
│       └── premium.enc     ← 暗号化して配信
│
└── .github/workflows/      収集・ビルド・デプロイ
```

**この分離の利点**

- コンテンツ更新にアプリのビルドが要らない（=毎日更新できる）
- 機能追加は `features/` にフォルダを1つ足すだけ（=3〜5年スケールする）
- ニュースツールは `features/news/` として吸収され、独立サービスではなくなる

### 3-2. 技術スタック

Version 1 と同じ（React 19 / TypeScript / Vite / Tailwind / shadcn-ui / Zustand / IndexedDB）。

ゼロベース見直しでも技術は変えない。理由は、Version 1 の `src/lib/tools/` 配下（歌詞レビュー、
MVアイデア、プロンプト図鑑）には**テスト付きの純粋ロジックが既にあり、これは資産**だから。
UIは捨ててもロジックは移植する。ここを作り直すのは損失にしかならない。

変えるのは**構成**（機能ごとの縦割り）と**コンテンツ基盤の追加**。

### 3-3. 課金の実装方式 — サーバーなしで成立させる

依頼の「Studioの有料プラン」という見せ方は正しい。ただし
Version 1 の憲章は**サーバー・DB・ログイン禁止**。ここが最大の技術課題になる。

**提案：ライセンスキー方式**

```
決済（Stripe / YouTubeメンバー確認）
        ↓
キー発行（karasui-PREMIUM-xxxx-xxxx）
        ↓
ユーザーがStudioに貼り付け
        ↓
アプリ内で署名を検証（オフラインで完結）
        ↓
Premiumコンテンツを復号して表示
```

| | この方式 | 一般的なログイン方式 |
|---|---|---|
| サーバー | 不要 | 必要 |
| 個人情報 | 一切持たない | メール等を保持 |
| オフライン | 動く | 動かない |
| 憲章との整合 | ◎ | ✕ |
| GitHub Pages | ◎ | ✕ |

**正直なトレードオフ**：クライアント側で復号する以上、技術力のある人が鍵を取り出して
Premiumコンテンツを抜くことは理論上可能。ただし現状（YouTubeメンバーへLINEでファイル配布）
より漏洩耐性は明確に高く、静的ホスティングを維持したまま実装できる唯一の現実解。

将来サーバーを持つ判断をしたときは、`core/entitlement/` の実装だけ差し替えればよい設計にする。

**移行**：最初の認証にYouTubeメンバーシップを使ってよい。ただし画面上の表示は
一貫して「Studio Premium」とし、YouTubeは**キーの入手経路の1つ**として扱う。
これで将来の独自課金移行時にユーザーの認識を変えずに済む。

## 4. プラン設計（最終仕様・2026-08-01確定）

### 権限は価格ではなく Role で管理する

```
free / premium / master
```

入手経路が違っても、最終的に同じ Role になる。画面側は「いくら払ったか」を見ない。

| 入手経路 | Role |
|---|---|
| YouTube「AIでMVを作りたい部」（¥1,290/月） | `premium` |
| YouTube「AIでMVを1か月でマスターしたい方向け」（¥5,600/月） | `master` |

**加入経路はYouTubeメンバーシップのみ。Studio直販は行わない**（2026-08-12決定）。
加入プランに応じて Role を自動付与し、
**Studioで別途登録し直す必要はない**。

実装は `src/core/entitlement/role.ts` に集約。画面側は必ず `useRole()` を通す。
YouTubeメンバーシップ名と価格の対応は `YOUTUBE_TIERS` が唯一の正。

### 認証

Studio はアカウントもサーバーも持たない（V1憲章のとおり）。
メンバーシップ加入者には Role を含むキーを配り、端末内で検証して Role を付与する。
`RoleSource`（`youtube` / `studio` / `none`）で入手経路も記録するので、
将来サーバーを持つ判断をしても、差し替えるのは `role.ts` だけで済む。

### 各Roleの中身

| | 無料 | Studio Premium | Studio Master |
|---|---|---|---|
| 種別 | ツール | **制作環境** | **学習環境（伴走）** |
| 価格 | ¥0 | **¥1,290 / 月** | **¥5,600 / 月** |
| スケール | 無限 | 無限 | **30名まで** |

**無料** … AI音楽ニュース（全文・日本語訳）／カラスイ Picks（冒頭）／AIツール図鑑／
制作ツール／曲の管理／プロンプト工房（基本セット）／**データの書き出し**

**Premium** … Premium限定ツール／プロンプトライブラリ／制作テンプレート／
AI音楽ニュース詳細版／カラスイ Picks 全文／制作履歴／お気に入り／新機能先行公開

**Master** … Premiumのすべて ＋ 作品添削／AI音楽レビュー／
**Discord Master限定コミュニティ**／Master限定ライブ／優先サポート

### Discord

Master のときだけ案内する。**招待URLは公開コードに置かない**（2026-08-08変更）。
プラン画面のMasterカードには案内文のみを表示し、実際のURLは
ライセンスキー送付と同じく公式LINEから手動でお送りする。
詳細は `PROJECT_SPEC.md` §6 を参照。

## 5. Substack導線

**押し売りにしないための4つのルール**

1. **場所**：ニュースとPicksを読み終わった直後に1枚だけ。モーダルは使わない
2. **文言**：「登録してください」ではなく「今週のまとめを受け取りませんか？」
3. **閉じられる**：×を押したら30日出さない
4. **有料会員には出さない**：既に情報が届いているため（プロトタイプで実装済み）

憲章第六原則「制作の邪魔をしない」を守るための設計。
Substackは無料登録を前提とし、Studio内で完結する体験を壊さない。

## 6. 開発フェーズ案

| Phase | 内容 | 目的 |
|---|---|---|
| **0** | 設計合意・プロトタイプ確認 | ←**いまここ** |
| 1 | プロジェクト基盤＋デザインシステム＋シェル | 土台 |
| 2 | コンテンツ基盤＋ニュース機能移植 | 毎日更新される状態を作る |
| 3 | トップページ（今日のスタジオ） | 「毎日開く」の実現 |
| 4 | 制作ツールをV1から移植 | 機能面でV1と並ぶ |
| 5 | Picks・プロンプト工房・ツール図鑑 | コンテンツを厚くする |
| 6 | プラン基盤（ライセンスキー） | 課金開始 |
| 7 | 別URLで公開・並行運用 | 検証 |
| 8 | データ移行 → 切替 | 完了 |

Phase 2 を先に置いているのは、**「毎日更新されるコンテンツがある」状態が
このプロダクトの心臓部**だから。ここが動けば、あとは足すだけになる。

## 7. 決定事項と、残る論点

### 決定済み（2026-07-31）

| 項目 | 決定 |
|---|---|
| Studio Premium | ¥980 / 月 |
| Studio Master | ¥5,600 / 月（現行YouTubeメンバーシップと同額・据え置き） |
| Master 人数上限 | **30名**（状況を見て増減） |
| 制作履歴・お気に入り | Premium に含める（手当て①②とセット） |
| V1ユーザーへの対応 | **Premiumを1年間無償**。その後は運営状況で判断 |
| データエクスポート | **無料のまま維持**（人質化しない） |
| Premiumの価値モデル | 毎週コンテンツではなく**プロダクトの進化**（§1-2） |
| 独自ドメイン | 後回し。プロダクトを育てるのが先 |
| V1データ移行 | 最低限でよい。将来対応で十分 |

### 残る論点

- 決済手段（Stripe導入の時期）とライセンスキー発行の運用フロー
- Premium限定ツールを具体的に何にするか（Phase 5で検討）
- 公開時のURL（GitHub Pages のサブパスで開始し、後からドメインを当てる）
