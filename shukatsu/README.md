# 夫婦引き継ぎ書

Studio Next とは無関係の、個人用の引き継ぎ書（エンディングノート）です。単一の HTML ファイルで完結しています。

- `index.html` … アプリ本体（CSS・JS・データ・キャラクターをすべて内包）

配信先は2つあります。

| | 保存先 | 用途 |
|---|---|---|
| **Artifact**（claude.ai の共有リンク） | ページ自体。共有相手と同じ内容を見られる | 二人で書いて共有する本番 |
| **GitHub Pages** | 各端末の localStorage。人ごとに分離 | Claudeを使っていない人に見せる公開版 |

### 公開版は人ごとに作る

```
https://karasui1014.github.io/studio-next/shukatsu/        一覧（誰のを開くか選ぶ）
https://karasui1014.github.io/studio-next/shukatsu/otto/   夫のノート
https://karasui1014.github.io/studio-next/shukatsu/tsuma/  妻のノート
```

誰のぶんを作るかは `shukatsu/people.json` で決めます。

```bash
python3 shukatsu/build-standalone.py                     # people.json の通りに作る
python3 shukatsu/build-standalone.py otto=太郎 tsuma=花子   # 名前を指定（設定も書き換わる）
python3 shukatsu/build-standalone.py --list              # いま誰のぶんがあるか
```

`id` は URL に使うので半角英小文字・数字・ハイフンのみ。`name` は画面に出る名前です。

> **なぜ人ごとに分ける必要があるのか**
>
> localStorage は origin（ドメイン）単位で共有されます。`/shukatsu/otto/` と
> `/shukatsu/tsuma/` はパスが違うだけで同じ保存場所を読み書きするため、
> ページを分けただけでは二人の記入が混ざります。
>
> そこでビルド時に `var NOTE = {};` を `var NOTE = {"id":"otto","name":"夫"};`
> に差し替え、保存キーに id を混ぜています（`endingnote.v1.otto` /
> `endingnote.v1.tsuma`）。分離はテストで固定してあります。
>
> Artifact 版では `NOTE` が空のままなので、保存キーも表示も従来どおりです。

公開版は `window.claude` が無い環境で動くので localOnly モードになり、
**書いた内容が公開されることはありません**（各自の端末に留まります）。
このリポジトリは Public なので、記入済みの内容は絶対にコミットしないでください。

`public/` は `vite build` がそのまま `dist/` にコピーするため、既存の公開
ワークフロー（`.github/workflows/deploy.yml`、main への push で起動）に
そのまま乗ります。

## 案内役

案内役のイラストが各章にセリフを出します。立ち絵は `assets/character-sheet.webp`
（ローファイ探偵のキャラクターシート）から切り出した**原画**で、`index.html` の `ART` に
WebP の data URI として埋め込まれています（8点・約185KB）。

**アプリ内にキャラクター名は表示しません。** 吹き出しはセリフだけで、肩書きは出しません。
ファイル名や下の表のキーが `akari-*` なのは、元絵の出どころを示すためです。

| キー | 使うところ |
|---|---|
| `normal` | 章の見出し |
| `think` | 聞き込みモードの質問 |
| `surprise` | 予備 |
| `point` | 注意書き（指を立てた表情） |
| `smile` | 表紙・説明 |
| `wink` | 完了したとき |
| `cat` | 上部バー（相棒のシャム） |
| `front` | 表紙の全身・聞き込み完了画面 |

### 立ち絵を作り直す

```bash
cd shukatsu
python3 assets/build-art.py        # 切り出して index.html の ART に埋め込む
python3 assets/build-art.py --crop # 切り出しだけ
```

`assets/character-sheet.webp` が元絵です。差し替えるときは、
`build-art.py` の `BOXES`（シート上の切り出し位置）を測り直してください。
背景は外周からの塗りつぶしで抜いているので、地色が均一なシートであれば
そのまま通ります。Pillow が必要です（`pip install Pillow`）。

配色もこのシートの COLOR PALETTE から取っています
（生成り `#F5F1E8` ／ タン `#D9B98C` ／ 浅葱 `#4C888C` ／ 焦茶 `#8A7A67` ／ 墨緑 `#3E4540`）。

## 仕組み

書いた内容は `<script type="application/json" id="note-data">` に入り、
「保存する」を押すと **ページ自体を新しいバージョンとして publish し直す**ことで残ります
（`claude.use("artifact")` の `publish`）。サーバーもデータベースも使いません。

- ページの正本は `<style id="app-css">` と `<script id="app-js">` の2つ。
  保存時はこの2つを読み直して完全な HTML を組み立てます（DOM は直列化しません）。
- 保存前の内容は localStorage に下書きとして常に控えます。保存に失敗しても消えません。
- Artifact の外（ローカルのファイルとして開くなど）では localStorage だけで動きます。
- 閲覧権限しかない人が保存を押すと `not_writer` が返り、閲覧専用の表示に切り替わります。

## 書きやすさのための仕掛け

- **聞き込みモード** … 未記入の項目だけを一問ずつ全画面で聞く。Enter で次へ、選択式は選ぶと自動で次へ。
- **候補チップ** … 「ありか」系の項目は `金庫` `寝室の引き出し` などをタップで入力。
- **未記入だけ表示** … 章の中で空欄だけに絞る。
- 入力欄は 16px 以上（iOS で勝手に拡大しない）。電話番号などは `inputmode` を指定。
- 表紙の名前は章1「氏名」から自動で拾うので、同じ名前を二度書かせない。

## 中身

18章。うち最初の2章は「読む」章（`kind:"guide"`）で、残りが「書く」章です。

**読む章（残された人のための手順）**

| 章 | 内容 |
|---|---|
| 01 そのときの手順 | 死亡診断書のコピーから相続登記まで13件。期限順に、窓口・要るもの・手順つき |
| 02 申請しないと出ないお金 | 葬祭費・埋葬料・遺族年金・団信など14件。金額と時効つき |

どちらも各項目に「済」のチェックと「いつ・どこで済ませたか」のメモがつきます。
**記入率には混ぜず**、もくじには「n / m 済」と出ます（書くものではなく、やるものなので）。
表紙のいちばん上に緊急カードを置き、最初に開く人がここに来られるようにしています。

> 期限と金額は 2026年8月時点で確認したものです。制度改正や自治体で変わるので、
> 章の冒頭に注意書きを出し、「確かめる先」に公式の窓口を載せています。
> 内容を更新したら、この日付と注意書きも直してください。

**書く章**

わたしのこと／家族・親族／医療の希望／介護の希望／お金のこと／保険／
不動産・大切なもの／デジタルのこと／葬儀の希望／お墓・供養／訃報の連絡先／
遺言・相続／ペット／書類のありか／大切な人へ／やることリスト

章と項目は `SCHEMA` 配列だけで決まります。

```js
// 書く章の項目
{k:"key", l:"見出し", t:"text|long|date|choice|list|tasks",
 h:"補足", o:[選択肢], c:[列定義], q:[候補チップ], im:"tel|numeric"}

// 読む章の項目
{k:"key", l:"見出し", t:"guide", items:[
  {id:"a1", g:"当日〜数日", pri:"最優先", t:"見出し", due:"期限",
   amount:"いくら", who:"だれが", where:"どこへ", need:"要るもの",
   how:["手順1","手順2"], note:"注意"}
]}
```

章には `say`（案内役のセリフ）と、必要なら `warn`（注意書き）を持たせます。
`kind:"guide"` をつけると、記入率から外れ、聞き込みモードでも飛ばされます。

## アイコンとファビコン

キャラクターシートの顔まわりを切り出し、瞳と同じ深い浅葱（`#2E5F63`）の
角丸にのせています。16pxでは細部が潰れますが、タン色の帽子と暗い髪の
かたまりで見分けがつきます。

```bash
python3 shukatsu/assets/build-icons.py
```

| ファイル | 用途 |
|---|---|
| `icon-32.png` / `icon-48.png` | ブラウザのタブ |
| `apple-touch-icon.png` (180) | iOSのホーム画面。**角丸なし**（iOSが自分で丸めるため） |
| `icon-192.png` / `icon-512.png` | Androidのホーム画面・スプラッシュ |
| `icon-maskable.png` (512) | Androidのアダプティブ用。外側20%が削られても顔が残る余白 |

出力先は `public/shukatsu/icons/`。あわせて `index.html` の `FAVICON`
（48pxのdata URI）も差し替わります。Artifact版は外部ファイルを読めないため、
そちらは埋め込みで持ちます。

`app.webmanifest` を人ごとに置いてあるので、「ホーム画面に追加」すると
その人のノートが直接開きます（`display: standalone`、テーマ色 `#2E5F63`）。

切り出す位置や背景色は `build-icons.py` の `BOX` と `BG` で変えられます。

## 暗証番号による施錠

**開くには暗証番号が要ります。1時間さわらなければ自動で鍵がかかります。**

画面を隠すだけの鍵は開発者ツールで素通りされるので、**本文そのものを暗号化**しています。

| | |
|---|---|
| 鍵の導出 | PBKDF2-SHA256、25万回、16バイトのランダムsalt |
| 暗号化 | AES-GCM 256bit（改ざんも検知される） |
| 保存の形 | `endingnote.v1.<id>.vault` = `{salt, iv, ct, at}` |
| 解錠中の鍵 | `sessionStorage` に期限つき。タブを閉じれば消える |
| 失効 | 最後の操作から1時間。`visibilitychange` と30秒ごとの点検で施錠 |

暗証番号を知らない限り、localStorage にも公開HTMLにも意味のない文字列しか残りません。
上部の 🔒 でいつでも手動で施錠できます。

> **忘れると誰にも開けません。** 暗号化しているので復旧手段はありません。
> 初回に「紙に書いて保管する」チェックを必須にしているのはこのためです。
> 終活の文書としては、**パートナーに番号を伝えておかないと本末転倒**になります。
> ヒント（暗証番号そのものではなく思い出す手がかり）を1つ登録できます。

Web Crypto が使えない環境（一部の `file://` など）では中身を開かず、
https から開き直すよう案内します。

### 名前は画面から変えられる

表紙の「この引き継ぎ書の名前」でいつでも変更でき、ビルドし直す必要はありません。
入口の一覧にも反映されます。そのため**名前だけは暗号化せず** `…​.label` に置いています
（一覧ページが読むため）。本文は読めません。
